= 可观测性

可观测性是指从外部观察运行系统内部状态的能力。
它由三大支柱组成：日志、指标和追踪。

对于指标和追踪，Spring Boot 使用 {url-micrometer-docs}/observation[Micrometer Observation]。
要创建你自己的观测（这将产生指标和追踪），你可以注入一个 javadoc:io.micrometer.observation.ObservationRegistry[]。

[source,java]
----
import io.micrometer.observation.Observation;
import io.micrometer.observation.ObservationRegistry;

import org.springframework.stereotype.Component;

@Component
public class MyCustomObservation {

	private final ObservationRegistry observationRegistry;

	public MyCustomObservation(ObservationRegistry observationRegistry) {
		this.observationRegistry = observationRegistry;
	}

	public void doSomething() {
		Observation.createNotStarted("doSomething", this.observationRegistry)
			.lowCardinalityKeyValue("locale", "en-US")
			.highCardinalityKeyValue("userId", "42")
			.observe(() -> {
				// Execute business logic here
			});
	}

}
----

注意：低基数标签会被添加到指标和追踪中，而高基数标签只会被添加到追踪中。

类型为 javadoc:io.micrometer.observation.ObservationPredicate[]、javadoc:io.micrometer.observation.GlobalObservationConvention[]、javadoc:io.micrometer.observation.ObservationFilter[] 和 javadoc:io.micrometer.observation.ObservationHandler[] 的 bean 会自动注册到 javadoc:io.micrometer.observation.ObservationRegistry[] 上。
你还可以额外注册任意数量的 javadoc:org.springframework.boot.micrometer.observation.autoconfigure.ObservationRegistryCustomizer[] beans 来进一步配置注册表。

提示：JDBC 的可观测性可以通过一个独立项目进行配置。
https://github.com/jdbc-observations/datasource-micrometer[Datasource Micrometer 项目] 提供了一个 Spring Boot starter，当调用 JDBC 操作时会自动创建观测。
更多信息请参阅 https://jdbc-observations.github.io/datasource-micrometer/docs/current/docs/html/[参考文档]。

提示：R2DBC 的可观测性内置于 Spring Boot 中。
要启用它，请将 `io.r2dbc:r2dbc-proxy` 依赖添加到你的项目中。


[[actuator.observability.context-propagation]]
== 上下文传播

可观测性支持依赖于 https://github.com/micrometer-metrics/context-propagation[Context Propagation 库] 来在线程和响应式管道之间转发当前观测。
默认情况下，javadoc:java.lang.ThreadLocal[] 值不会在响应式操作符中自动恢复。
此行为由 configprop:spring.reactor.context-propagation[] 属性控制，可设置为 `auto` 以启用自动传播。

如果你在使用 javadoc:org.springframework.scheduling.annotation.Async[format=annotation] 方法并且 javadoc:org.springframework.core.task.AsyncTaskExecutor[] 是自动配置的，你需要通过 configprop:spring.task.execution.propagate-context[] 属性选择启用上下文传播。

如果你自己配置 javadoc:org.springframework.core.task.AsyncTaskExecutor[]，则需要注册一个 javadoc:org.springframework.core.task.support.ContextPropagatingTaskDecorator[] bean，如下例所示：

[source,java]
----
import org.springframework.context.annotation.Bean;
import org.springframework.context.annotation.Configuration;
import org.springframework.core.task.support.ContextPropagatingTaskDecorator;

@Configuration(proxyBeanMethods = false)
class ContextPropagationConfiguration {

	@Bean
	ContextPropagatingTaskDecorator contextPropagatingTaskDecorator() {
		return new ContextPropagatingTaskDecorator();
	}

}
----

关于观测的更多细节，请参阅 {url-micrometer-docs}/observation[Micrometer Observation 文档]。


[[actuator.observability.common-tags]]
== 通用标签

通用标签通常用于对运行环境进行维度下钻，例如主机、实例、区域、堆栈等。
通用标签作为低基数标签应用于所有观测，并且可以进行配置，如下例所示：

[configprops,yaml]
----
management:
  observations:
    key-values:
      region: "us-east-1"
      stack: "prod"
----
前面的示例分别向所有观测值添加了值为 `us-east-1` 和 `prod` 的 `region` 和 `stack` 标签。

[[actuator.observability.preventing-observations]]
== 阻止观测

如果您希望阻止某些观测被报告，可以使用 configprop:management.observations.enable[] 属性：

[configprops,yaml]
----
management:
  observations:
    enable:
      denied:
        prefix: false
      another:
        denied:
          prefix: false
----
前面的示例将阻止所有名称以 `denied.prefix` 或 `another.denied.prefix` 开头的观测。

提示：如果你想阻止 Spring Security 报告观测，请将属性 configprop:management.observations.enable.spring.security[] 设置为 `false`。

如果你需要对观测的阻止进行更精细的控制，可以注册类型为 javadoc:io.micrometer.observation.ObservationPredicate[] 的 beans。
仅当所有 javadoc:io.micrometer.observation.ObservationPredicate[] beans 对该观测返回 `true` 时，才会报告观测。

[source,java]
----
import io.micrometer.observation.Observation.Context;
import io.micrometer.observation.ObservationPredicate;

import org.springframework.stereotype.Component;

@Component
class MyObservationPredicate implements ObservationPredicate {

	@Override
	public boolean test(String name, Context context) {
		return !name.contains("denied");
	}

}
----

前面的示例将阻止所有名称包含 "denied" 的观测。


[[actuator.observability.annotations]]
== Micrometer Observation 注解支持

要启用对诸如 javadoc:io.micrometer.observation.annotation.Observed[format=annotation]、javadoc:io.micrometer.core.annotation.Timed[format=annotation]、javadoc:io.micrometer.core.annotation.Counted[format=annotation]、javadoc:io.micrometer.core.aop.MeterTag[format=annotation] 和 javadoc:io.micrometer.tracing.annotation.NewSpan[format=annotation] 等可观测性注解的扫描，请将 configprop:management.observations.annotations.enabled[] 属性设置为 `true`。
还需要依赖 `org.aspectj:aspectjweaver`，它是 `spring-boot-starter-aspectj` 的一部分。
此功能由 Micrometer 直接支持。
请参考 {url-micrometer-docs-concepts}/timers.html#_the_timed_annotation[Micrometer]、link:{url-micrometer-docs-observation}/components.html#micrometer-observation-annotations[Micrometer Observation] 和 {url-micrometer-tracing-docs}/api.html#_aspect_oriented_programming[Micrometer Tracing] 参考文档。

注意：当你对已经进行过仪器化的方法或类（例如 xref:reference:actuator/metrics.adoc#actuator.metrics.supported.spring-data-repository[Spring Data 仓库] 或 xref:reference:actuator/metrics.adoc#actuator.metrics.supported.spring-mvc[Spring MVC 控制器]）添加注解时，将会得到重复的观测。
在这种情况下，你可以使用 xref:reference:actuator/observability.adoc#actuator.observability.preventing-observations[属性] 或 javadoc:io.micrometer.observation.ObservationPredicate[] 禁用自动仪器化，并依赖你的注解，或者你可以移除你的注解。


[[actuator.observability.opentelemetry]]
== OpenTelemetry 支持

注意：在你的应用程序中有多种方式支持 https://opentelemetry.io/[OpenTelemetry]。
你可以使用 https://opentelemetry.io/docs/zero-code/java/agent/[OpenTelemetry Java Agent] 或 https://opentelemetry.io/docs/zero-code/java/spring-boot-starter/[OpenTelemetry Spring Boot Starter]，它们由 OTel 社区支持；指标和追踪使用 OTel 库定义的语义约定。
本文档描述了由 Spring 团队官方支持的 OpenTelemetry，使用 Micrometer 和 OTLP 导出器；
指标和追踪使用 Spring 项目文档中描述的语义约定，例如 {url-spring-framework-docs}/integration/observability.html[Spring Framework]。

Spring Boot 的 actuator 模块包含对 OpenTelemetry 的基本支持。

它提供了一个类型为 javadoc:io.opentelemetry.api.OpenTelemetry[] 的 bean，并且如果应用程序上下文中存在类型为 javadoc:io.opentelemetry.sdk.trace.SdkTracerProvider[]、javadoc:io.opentelemetry.context.propagation.ContextPropagators[]、javadoc:io.opentelemetry.sdk.logs.SdkLoggerProvider[] 或 javadoc:io.opentelemetry.sdk.metrics.SdkMeterProvider[] 的 beans，它们会自动注册。
此外，它还提供了一个 javadoc:io.opentelemetry.sdk.resources.Resource[] bean。
自动配置的 javadoc:io.opentelemetry.sdk.resources.Resource[] 的属性可以通过 configprop:management.opentelemetry.resource-attributes[] 配置属性进行配置。
自动配置的属性将与来自 `OTEL_RESOURCE_ATTRIBUTES` 和 `OTEL_SERVICE_NAME` 环境变量的属性合并，通过配置属性配置的属性优先于环境变量中的属性。


如果你定义了自己的 javadoc:io.opentelemetry.sdk.resources.Resource[] bean，则情况不再如此。

注意：Spring Boot 不提供 OpenTelemetry 指标或日志的自动导出。
仅当与 xref:actuator/tracing.adoc[Micrometer Tracing] 一起使用时，才会自动配置 OpenTelemetry 追踪的导出。


[[actuator.observability.opentelemetry.disabling]]
=== 禁用 OpenTelemetry

可以通过将 configprop:management.opentelemetry.enabled[] 属性设置为 `false` 来禁用 OpenTelemetry 支持。
其行为类似于 https://opentelemetry.io/docs/specs/otel/configuration/sdk-environment-variables/#general-sdk-configuration[`OTEL_SDK_DISABLED`] 环境变量（但取反）：当 SDK 被禁用时，指标、追踪和日志将使用无操作实现。
上下文传播器不受影响，继续正常运行。

注意：请记住，Spring Boot 不使用 OpenTelemetry 的指标功能，因此即使禁用 OpenTelemetry，指标可能仍然启用。


[[actuator.observability.opentelemetry.environment-variables]]
=== 环境变量

Spring Boot 支持 https://opentelemetry.io/docs/specs/otel/configuration/sdk-environment-variables/[OpenTelemetry SDK 环境变量] 的一个子集。
这些环境变量在启动时自动映射到 Spring Boot 配置属性。
当环境变量具有特定于信号的变体（例如 `OTEL_EXPORTER_OTLP_TRACES_ENDPOINT`）和通用变体（`OTEL_EXPORTER_OTLP_ENDPOINT`）时，特定于信号的变体优先并直接使用。
当使用通用变体作为回退时，特定于信号的路径（`v1/traces`、`v1/metrics` 或 `v1/logs`）会附加到它后面。
例如，设置 `OTEL_EXPORTER_OTLP_ENDPOINT=http://collector:4318` 会导致追踪的 `http://collector:4318/v1/traces`。

可以通过将 configprop:management.opentelemetry.map-environment-variables[] 设置为 `false` 来禁用此映射。

[[actuator.observability.opentelemetry.environment-variables.resource]]
==== 资源

以下环境变量配置 OpenTelemetry 资源：

* https://opentelemetry.io/docs/specs/otel/configuration/sdk-environment-variables/#general-sdk-configuration[`OTEL_RESOURCE_ATTRIBUTES`]
* https://opentelemetry.io/docs/specs/otel/configuration/sdk-environment-variables/#general-sdk-configuration[`OTEL_SERVICE_NAME`]

注意：`OTEL_RESOURCE_ATTRIBUTES` 环境变量由一系列键值对组成。
例如：`key1=value1,key2=value2,key3=spring%20boot`。

[[actuator.observability.opentelemetry.environment-variables.unsupported]]
==== 不支持的环境变量

其他在 https://opentelemetry.io/docs/specs/otel/configuration/sdk-environment-variables/[OpenTelemetry 文档] 中描述的环境变量不受支持。

如果你希望 OpenTelemetry SDK 指定的所有环境变量都生效，你必须提供自己的 `OpenTelemetry` bean。

警告：这样做将关闭 Spring Boot 的 OpenTelemetry 自动配置，并可能破坏内置的可观测性功能。

首先，添加对 `io.opentelemetry:opentelemetry-sdk-extension-autoconfigure` 的依赖以获取 https://opentelemetry.io/docs/languages/java/configuration/#zero-code-sdk-autoconfigure[OpenTelemetry 的零代码 SDK 自动配置模块]，然后添加以下配置：

[source,java]
----
import io.opentelemetry.api.OpenTelemetry;
import io.opentelemetry.sdk.autoconfigure.AutoConfiguredOpenTelemetrySdk;

import org.springframework.context.annotation.Bean;
import org.springframework.context.annotation.Configuration;

@Configuration(proxyBeanMethods = false)
class AutoConfiguredOpenTelemetrySdkConfiguration {

	@Bean
	OpenTelemetry autoConfiguredOpenTelemetrySdk() {
		return AutoConfiguredOpenTelemetrySdk.initialize().getOpenTelemetrySdk();
	}

}
----



[[actuator.observability.opentelemetry.logging]]
=== 日志

javadoc:org.springframework.boot.opentelemetry.autoconfigure.logging.OpenTelemetryLoggingAutoConfiguration[] 配置 OpenTelemetry 的 javadoc:io.opentelemetry.sdk.logs.SdkLoggerProvider[]。
通过 OTLP 导出日志由 javadoc:org.springframework.boot.opentelemetry.autoconfigure.logging.otlp.OtlpLoggingAutoConfiguration[] 支持，它通过 HTTP 或 gRPC 启用 OTLP 日志导出。

注意：如果你需要对 OTLP 日志记录导出器应用高级自定义，请考虑注册 javadoc:org.springframework.boot.opentelemetry.autoconfigure.logging.otlp.OtlpHttpLogRecordExporterBuilderCustomizer[] 或 javadoc:org.springframework.boot.opentelemetry.autoconfigure.logging.otlp.OtlpGrpcLogRecordExporterBuilderCustomizer[] beans。
这些将在创建 javadoc:io.opentelemetry.exporter.otlp.http.logs.OtlpHttpLogRecordExporter[] 或 javadoc:io.opentelemetry.exporter.otlp.logs.OtlpGrpcLogRecordExporter[] 之前被调用。
自定义器优先于自动配置应用的任何内容。

然而，虽然存在 `SdkLoggerProvider` bean，但 Spring Boot 默认不支持将日志桥接到此 bean。
这可以通过第三方日志桥接器完成，如 xref:reference:actuator/loggers.adoc#actuator.loggers.opentelemetry[使用 OpenTelemetry 进行日志记录] 部分所述。



[[actuator.observability.opentelemetry.metrics]]
=== 指标

Spring 产品组合中的指标选择是 Micrometer，这意味着指标不是通过 OpenTelemetry 的 javadoc:io.opentelemetry.sdk.metrics.SdkMeterProvider[] 收集和导出的。
Spring Boot 不提供 `SdkMeterProvider` bean。

然而，Micrometer 指标可以通过 OTLP 导出到任何支持 OpenTelemetry 的后端，使用 javadoc:io.micrometer.registry.otlp.OtlpMeterRegistry[]，如 xref:reference:actuator/metrics.adoc#actuator.metrics.export.otlp[使用 OTLP 的指标] 部分所述。

注意：Micrometer 的 OTLP 注册表不使用 `Resource` bean，但设置 `OTEL_RESOURCE_ATTRIBUTES`、`OTEL_SERVICE_NAME` 或 configprop:management.opentelemetry.resource-attributes[] 是有效的。

[[actuator.observability.opentelemetry.metrics.api-and-sdk]]
==== 通过 OpenTelemetry API 和 SDK 的指标

如果你或你包含的依赖使用了 OpenTelemetry 的 javadoc:io.opentelemetry.api.metrics.MeterProvider[]，这些指标不会被导出。

我们强烈建议你使用 Micrometer 报告指标。
如果你包含的依赖使用了 OpenTelemetry 的 `MeterProvider`，你可以在应用程序中包含以下配置来配置一个 `MeterProvider` bean，然后你需要将其连接到你的依赖中：

[source,java]
----
import java.time.Duration;

import io.opentelemetry.exporter.otlp.http.metrics.OtlpHttpMetricExporter;
import io.opentelemetry.sdk.metrics.SdkMeterProvider;
import io.opentelemetry.sdk.metrics.export.MetricExporter;
import io.opentelemetry.sdk.metrics.export.MetricReader;
import io.opentelemetry.sdk.metrics.export.PeriodicMetricReader;
import io.opentelemetry.sdk.resources.Resource;

import org.springframework.context.annotation.Bean;
import org.springframework.context.annotation.Configuration;

@Configuration(proxyBeanMethods = false)
class OpenTelemetryMetricsConfiguration {

	@Bean
	OtlpHttpMetricExporter metricExporter() {
		String endpoint = "http://localhost:4318/v1/metrics";
		return OtlpHttpMetricExporter.builder().setEndpoint(endpoint).build();
	}

	@Bean
	PeriodicMetricReader metricReader(MetricExporter exporter) {
		Duration interval = Duration.ofMinutes(1);
		return PeriodicMetricReader.builder(exporter).setInterval(interval).build();
	}

	@Bean
	SdkMeterProvider meterProvider(Resource resource, MetricReader metricReader) {
		return SdkMeterProvider.builder().registerMetricReader(metricReader).setResource(resource).build();
	}

}
----

此配置还通过 HTTP 启用 OTLP 指标导出。



[[actuator.observability.opentelemetry.tracing]]
=== 链路追踪

如果使用了 Micrometer 链路追踪，javadoc:org.springframework.boot.micrometer.tracing.opentelemetry.autoconfigure.OpenTelemetryTracingAutoConfiguration[] 配置 OpenTelemetry 的 javadoc:io.opentelemetry.sdk.trace.SdkTracerProvider[]。
通过 OTLP 导出链路追踪由 javadoc:org.springframework.boot.micrometer.tracing.opentelemetry.autoconfigure.otlp.OtlpTracingAutoConfiguration[] 启用，它支持通过 HTTP 或 gRPC 使用 OTLP 导出链路追踪。

我们强烈建议使用 Micrometer Observation 或 Tracing API，而不是直接使用 OpenTelemetry API。
