# 校验规则

## 目标

`npm run validate` 用于在构建前发现翻译过程中常见的问题，避免破坏 Antora 页面结构或泄露密钥。

`npm run audit:completeness` 用于对比上游 AsciiDoc、中文译文和构建产物，发现代码块缺失、正文块缺失、结构元素丢失以及自定义宏未渲染等完整性问题。

## 校验范围

- 全量翻译计划中的页面和 partial 是否已经生成。
- AsciiDoc listing/source 代码块分隔符是否成对。
- AsciiDoc tabs/example 分隔符 `======` 是否成对。
- `[source,...]`、`[subs=...]`、`[configprops,...]` 等代码块属性后是否紧跟 `----` 分隔符。
- 翻译后页面是否保留上游页面中的 `xref:` 目标。
- `xref:`、`link:`、URL 宏中的可见链接文本是否已翻译，目标和属性是否保留。
- Java API、Kotlin API、Maven Plugin API 和 Gradle Plugin API 可以从本地 `xref:` 改为官方外部链接。
- 正文中的 `javadoc:` 内联宏必须渲染为可点击 API 链接，显示文本使用短类名；`format=annotation` 时显示为 `@短类名`。
- 页面引用的 `partial$...` include 目标必须存在；官方构建生成但源仓库不包含的片段必须从官方 Gradle 生成产物导入，不能用中文占位 partial 补齐。
- 译文源文件和构建产物不得残留“当前中文站暂未纳入完整生成内容”“该片段由官方构建流程生成”“该表格片段由官方构建流程生成”或“该请求或响应示例由官方构建流程生成”等占位文本。
- 上游出现的专业术语、官方标识和必须保留的技术文本是否仍出现在译文中；术语按词边界和常见复数匹配，避免把 `WARNING` 中的 `WAR` 当成术语。
- 标题、导航、面包屑来源和普通段落中不得出现“中文解释 (英文标识)”这类重复并列；官方 endpoint ID、配置键、类名、专名和协议名可以保留英文，但不能再额外附同义中文解释。
- 代码块、inline code、配置键、类名、宏目标之外是否存在高置信度英文自然语言残留。
- 仓库文本文件中是否出现疑似 API key。

## 完整性审计规则

完整性审计按全量翻译计划逐页执行，不调用 DeepSeek，也不会修改译文。

审计必须检查：

- 上游页面和译文页面的 anchors、heading 层级、listing/source 块、表格块、example/tabs 块数量和顺序是否一致。
- `include::`、`xref:`、`link:`、`image::` 等宏的目标是否保留，链接可见文本是否仍残留英文自然语言。
- 每个小节的可见正文块数量是否明显少于上游；代码、命令、配置键、类名、URL 和保留术语不参与正文缺失判断。
- 上游 `include-code::` 宏在译文中必须保留为同名宏，或已经展开为等价的 `[source,...]` 代码块。
- 构建产物中不得出现原始 `include-code::`、`javadoc:` 文本、`Unresolved include directive`、未解析 `{url-...}` 属性或其他未解析 include 提示。
- 构建产物中不得出现生成型内容占位文本；出现占位文本时必须作为错误处理。

完整性审计发现高置信度问题时必须输出中文错误信息，并写入 `reports/completeness-audit.jsonl` 和 Markdown 摘要报告。

## 示例代码规则

Spring Boot 官方文档使用 `include-code::` 引用源码示例。中文站必须同步官方示例源码，并在构建前把这些宏展开为 AsciiDoc 代码块。

允许同步的示例源码范围：

- `documentation/spring-boot-docs/src/main/java`
- `documentation/spring-boot-docs/src/main/kotlin`
- `documentation/spring-boot-docs/src/test/java`
- `documentation/spring-boot-docs/src/test/resources`

`include-code::` 解析失败、匹配到多个候选源码或 tag 截取失败时，校验必须失败，不能静默降级为占位文本。

官方 Gradle 生成内容缺失时，校验必须失败，不能静默降级为占位文本。

## Javadoc 内联链接规则

中文站不生成官方 Javadoc 和 Dokka 页面，但正文中的 `javadoc:` 内联宏必须在构建时转换为官方外部 API 链接。

渲染规则如下：

- `javadoc:org.springframework.boot...[]` 指向 Spring Boot 4.1.0 Java API。
- `javadoc:org.springframework...[]` 指向 Spring Framework 7.0.x Javadoc。
- `javadoc:{url-xxx}/...[]` 或 `javadoc:https://...[]` 使用目标自带的 API 根地址。
- `format=annotation` 的显示文本使用 `@短类名`，普通类使用短类名，显式链接文本优先使用显式文本。
- 无法解析目标、属性或 API 根地址时必须校验失败，不能在 HTML 中保留原始宏文本。

## 英文残留规则

校验会忽略代码块、inline code、URL、配置键、包名、类名、Javadoc/Dokka API 标识、官方 endpoint ID 和术语表中的专业术语。

以下情况应视为问题：

- 普通段落仍保留完整英文句子。
- `xref:`、`link:` 或 URL 宏方括号中的可见链接文本仍是英文短语。
- 导航标题仍是英文自然语言。
- 标题、导航项或面包屑来源写成 `条件评估报告 (conditions)`、`Spring 集成图 (integrationgraph)` 这类中英重复形式。
- 普通说明出现 `conditions endpoint`、`auto-configuration 类`、`annotation 注解` 这类可以自然中文化的混排。

以下情况允许保留英文：

- Maven、Gradle、REST API、Actuator、classpath、starter、JAR、WAR、native image 等专业术语。
- 官方 endpoint ID，例如 `conditions`、`httpexchanges`、`integrationgraph`。
- 代码、命令、配置属性、文件路径、包名、类名、HTTP 方法、Header、状态码和媒体类型。
- Java API 和 Kotlin API 外部参考链接。

## 密钥规则

任何形如 `sk-` 后跟较长字母数字串的文本都视为疑似密钥泄露。

允许 `.env.example` 使用中文占位值，但不允许真实密钥进入仓库。

DeepSeek API key 只能从本地环境变量或 `.env` 读取，不允许写入脚本、文档、测试快照或报告。

## 失败处理

校验发现错误时，脚本必须输出中文错误信息并以非零退出码结束。

## CI 测试隔离规则

GitHub Actions 在 clean checkout 中运行，测试不能依赖本地已经存在的 `build/site`、`reports` 或其他忽略产物。

构建脚本的单元测试如果 stub 了 Antora 构建或构建产物审计，也必须同时注入对应的文件列表、读写函数或空列表，避免测试误读开发机上的残留产物。
