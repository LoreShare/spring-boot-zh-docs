# 校验规则

## 目标

`npm run validate` 用于在构建前发现翻译过程中常见的问题，避免破坏 Antora 页面结构或泄露密钥。

## 校验范围

- 全量翻译计划中的页面和 partial 是否已经生成。
- AsciiDoc listing/source 代码块分隔符是否成对。
- AsciiDoc tabs/example 分隔符 `======` 是否成对。
- `[source,...]`、`[subs=...]`、`[configprops,...]` 等代码块属性后是否紧跟 `----` 分隔符。
- 翻译后页面是否保留上游页面中的 `xref:` 目标。
- `xref:`、`link:`、URL 宏中的可见链接文本是否已翻译，目标和属性是否保留。
- Java API、Kotlin API、Maven Plugin API 和 Gradle Plugin API 可以从本地 `xref:` 改为官方外部链接。
- 页面引用的 `partial$...` include 目标必须存在；官方构建生成但源仓库不包含的片段由中文占位 partial 补齐。
- 上游出现的不翻译术语是否仍出现在译文中；术语按词边界和常见复数匹配，避免把 `WARNING` 中的 `WAR` 当成术语。
- 代码块、inline code、配置键、类名、宏目标之外是否存在高置信度英文自然语言残留。
- 仓库文本文件中是否出现疑似 API key。

## 英文残留规则

校验会忽略代码块、inline code、URL、配置键、包名、类名、Javadoc/Dokka API 标识和术语表中的不翻译术语。

以下情况应视为问题：

- 普通段落仍保留完整英文句子。
- `xref:`、`link:` 或 URL 宏方括号中的可见链接文本仍是英文短语。
- 导航标题仍是英文自然语言。

以下情况允许保留英文：

- Maven、Gradle、REST API、Actuator、endpoint、classpath、starter、bean、annotation 等术语。
- 代码、命令、配置属性、文件路径、包名、类名、HTTP 方法和媒体类型。
- Java API 和 Kotlin API 外部参考链接。

## 密钥规则

任何形如 `sk-` 后跟较长字母数字串的文本都视为疑似密钥泄露。

允许 `.env.example` 使用中文占位值，但不允许真实密钥进入仓库。

## 失败处理

校验发现错误时，脚本必须输出中文错误信息并以非零退出码结束。
