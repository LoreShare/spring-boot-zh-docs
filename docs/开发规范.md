# 开发规范

## 基本原则

- 所有开发都在当前目录完成：`/Users/loreshare/ai-project/spring-doc/springboot/4.1.0`。
- 采用文档驱动开发：每个小功能先更新相关文档，再修改脚本或配置。
- 每完成一个小功能必须提交一次 Git commit，commit 信息使用中文。
- 项目文档、代码注释、脚本输出和错误提示默认使用中文。
- 不把任何 API key、token、cookie、密码或私密配置写入仓库。

## 目录约定

- `docs/`：中文方案、规范、验收和版权说明。
- `scripts/`：同步、翻译、校验等 Node.js 脚本。
- `test/`：Node.js 测试文件。
- `content/`：中文 Antora 内容源。
- `.cache/`：上游 Spring Boot 源码缓存，不提交。
- `build/site/`：Antora 生成的静态站点，不提交。

## 开发流程

1. 更新或新增对应文档。
2. 对脚本逻辑先写测试。
3. 运行测试，确认测试先失败。
4. 实现最小代码。
5. 运行测试和相关校验。
6. Git 提交，提交信息使用中文。

## 密钥管理

- DeepSeek API key 只通过环境变量 `DEEPSEEK_API_KEY` 或本地 `.env` 文件读取。
- `.env` 文件必须被 `.gitignore` 忽略。
- 仓库内可以提供 `.env.example`，但只能包含占位值。
