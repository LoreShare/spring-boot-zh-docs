# Antora 构建配置

## 目标

`npm run build` 使用 Antora 把 `versions/*/content/boot` 中的中文 AsciiDoc 内容生成到 `build/site`。

## 内容源

Antora playbook 使用当前仓库作为本地内容源：

```yaml
content:
  edit_url: false
  sources:
  - url: .
    branches: HEAD
    start_paths: versions/*/content/boot
```

## 中文组件

中文内容组件按 GA 版本位于 `versions/<version>/content/boot`，组件名保持为 `boot`。
当前 latest 版本为 `4.1.0`，后续新 GA 版本新增并保留对应目录。

导航使用上游顶层 `nav.adoc`，并通过其中的 include 指令串起全部已翻译模块：

- ROOT
- tutorial
- reference
- how-to
- build-tool-plugin
- cli
- api
- specification
- appendix

ROOT partial 只保留首页、文档概览、社区、系统要求、安装和升级等根入口。
已经由顶层 `nav.adoc` 单独 include 的模块，例如 tutorial、reference、how-to、build-tool-plugin、cli、api、specification 和 appendix，不能再在 ROOT partial 中重复添加同名顶层入口。

## 输出

- 静态站点目录：`build/site`
- 本地预览命令：`npm run serve`
- 默认预览地址：`http://localhost:8080`
- GitHub Pages 发布时通过 `SITE_URL` 覆盖站点地址，例如 `https://用户名.github.io/仓库名`。
- 构建产物必须包含 `build/site/.nojekyll`，避免 GitHub Pages 忽略 Antora 的 `_` 静态资源目录。
- 构建产物不能包含本机 `file://` 编辑链接；当前关闭 Antora 默认远程编辑地址，并在构建脚本中移除默认 UI 回退生成的本地 `Edit this Page` 链接。
- 构建产物会移除 Antora 默认 UI 生成的顶部黑色导航栏。本站保留左侧目录、面包屑、右侧 Contents 和版本选择器，把页面重心放在中文文档阅读上。
- 去除默认顶部导航时，不能只删除 header HTML。Antora 默认 UI 中 `.nav-container`、`.nav`、`.toolbar`、`.toc.sidebar .toc-menu` 都按原顶栏高度 `3.5rem` 计算 sticky 或 fixed 偏移，headerless 样式必须同步重置这些偏移，避免页面顶部空白、正文标题被面包屑遮挡或右侧 Contents 位置异常。
- 构建产物不能残留默认顶部导航标记，例如 `<header class="header">` 或 `id="topbar-nav"`。
- 当前内容包含 Maven 插件文档、Gradle 插件文档和 Actuator REST API 的 Antora 页面。
- 当前内容必须包含 Spring Boot 官方 Gradle 构建生成的配置属性表、依赖版本表、starter 表、测试 slice 表、自动配置类页面、Maven 插件 goal partial、Actuator REST Docs snippets 和示例输出。生成型内容缺失时，构建前校验必须失败，不能生成中文占位 partial。
- 当前内容不生成官方 Javadoc 和 Kotlin API 页面；Java API、Kotlin API、Maven Plugin API 和 Gradle Plugin API 入口保持为官方外部英文链接。
- 正文里的 `javadoc:` 内联宏通过本地 AsciiDoc 扩展渲染为官方外部 API 链接，不能在构建产物中残留原始宏文本。

## Docker 镜像

Docker 镜像采用多阶段构建：

- 构建阶段默认使用 `node:24-alpine` 安装依赖、补齐 Git 并执行 `npm run build`。
- 运行阶段默认使用 `nginx:alpine` 暴露构建得到的 `build/site` 静态站点。
- 容器监听 `80` 端口，本地可映射为 `8080`。
- Dockerfile 不使用额外的 `# syntax=` 构建前端指令，避免在基础镜像之外增加一次外部镜像拉取。

构建命令：

```bash
docker build -t spring-boot-zh-docs:4.1.0 .
```

运行命令：

```bash
docker run --rm -p 8080:80 --name spring-boot-zh-docs spring-boot-zh-docs:4.1.0
```

`.dockerignore` 可以排除 `node_modules`、`build`、`reports`、`.env` 等本地文件，但不能排除 `.git`。当前 Antora playbook 通过 `url: .` 和 `branches: HEAD` 读取本地内容源，构建阶段需要 Git 元数据解析 `HEAD`；最终 nginx 运行镜像不会复制 `.git`。

## AsciiDoc 扩展

Antora playbook 会注册本地 AsciiDoc 扩展来补齐 Spring 官方构建链中的自定义宏能力。

`javadoc:` 内联宏渲染规则：

- Spring Boot 类指向 `https://docs.spring.io/spring-boot/4.1.0/api/java/`。
- Spring Framework 类指向 `https://docs.spring.io/spring-framework/docs/7.0.x/javadoc-api/`。
- 带 `{url-xxx}` 或完整 URL 前缀的目标使用目标自身声明的 API 根地址。
- `format=annotation` 显示为 `@短类名`；普通类显示为短类名；显式链接文本保持原文。
