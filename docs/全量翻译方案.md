# Spring Boot 4.1.0 全量翻译方案

## 目标

在当前项目中把已同步的 Spring Boot `v4.1.0` Antora 文档源完整生成中文内容。

## 范围

翻译范围以本地缓存为准：

```text
.cache/spring-boot-v4.1.0/documentation/spring-boot-docs/src/docs/antora
```

纳入全量处理：

- `modules/**/pages/**/*.adoc`
- `modules/**/partials/**/*.adoc`
- 顶层 `nav.adoc`

复制但不翻译：

- `modules/ROOT/pages/redirect.adoc`
- 非 `.adoc` 文件，例如 `modules/reference/partials/dockerfile`

不在本轮范围：

- 官方构建时聚合的 Javadoc、Kotlin API、Actuator REST API、Maven 插件文档和 Gradle 插件文档。
- 这些内容在当前 Antora 源目录中不是可翻译 `.adoc` 源文件，链接保留为未解析外部内容。

## 分块策略

较大的 `.adoc` 页面不能一次性发送给 DeepSeek，否则容易超过输出上限或返回截断 JSON。

翻译脚本按行分块：

- 优先把单块控制在约 `12,000` 字符以内。
- 不在 `----` listing/source 代码块内部切分。
- 每个分块单独调用 DeepSeek。
- 如果分块只包含代码块、AsciiDoc 占位符或其他受保护内容，脚本直接复制原文，不调用 DeepSeek。
- 单个分块遇到 `fetch failed`、连接重置或 DNS/超时类瞬时网络错误时，先按同一分块重试，避免整页从头失败。
- 分块输出按原顺序拼接为完整页面。

## 断点续跑

- 如果目标文件已存在，默认跳过。
- 使用 `--force` 才覆盖重翻。
- 每次请求的 token 用量写入本地 usage 日志。
- usage 日志可以提交，因为不包含 API key。

## 命令

```bash
npm run translate:all
```

## 验收

全量翻译完成后：

```bash
npm test
npm run validate
npm run build
```

构建允许记录生成模块缺失导致的 xref 错误日志，但命令退出码必须为 0。
