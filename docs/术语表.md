# 翻译术语表

## 保持英文的专业术语

以下术语在中文文档中作为专业术语保持英文：

- Spring
- Spring Boot
- starter
- Actuator
- classpath
- JAR
- WAR
- profile
- native image
- GraalVM
- AOT
- Buildpack
- Maven
- Gradle
- Kotlin
- Java

以下词在代码、配置键、类名、包名、路径、HTTP API、endpoint ID、官方产品名或固定短语中保持英文；在普通自然语言说明中应按上下文翻译为中文：

- bean：普通说明中可译为“Bean”或“组件”，涉及 Spring 容器对象时保留 `bean` 或 `Bean`。
- endpoint：普通说明中译为“端点”，官方 endpoint ID（例如 `conditions`、`httpexchanges`）保持英文。
- auto-configuration：普通说明中译为“自动配置”，类名、包名、anchor 和官方专题标题中的 `AutoConfiguration` 保持英文。
- annotation：普通说明中译为“注解”，Java 注解名（例如 `@SpringBootApplication`）保持英文。
- REST API：作为协议/API 类型保持英文；普通说明中的动作和描述必须中文化。

## 必须保留的技术文本

- AsciiDoc anchors，例如 `[[getting-started]]`。
- AsciiDoc attributes，例如 `{spring-boot-version}`。
- xref 和 link 目标，例如 `xref:installing.adoc[]`。
- include 指令。
- 代码块和命令行示例。
- inline code。
- HTTP 方法、状态码、Header、媒体类型、JSON 字段名和 REST 请求/响应示例。
- Java 类名、包名、方法名、注解名。
- 配置键、属性名、环境变量名。
- 文件名、目录名、URL。
- 官方 endpoint ID，例如 `conditions`、`httpexchanges`、`integrationgraph`。

## 中文风格

- 普通说明翻译为自然、准确的技术中文。
- 保持技术文档语气，不使用营销式表达。
- 不在同一个标题、导航项或面包屑中写成“中文解释 (英文标识)”的重复并列；专业术语用英文，非专业说明用中文。
- 已有标准英文缩写或官方英文名称的专业术语不写中文全称，也不写中英并列；例如写 `AMQP`、`AOP`、`JMX`、`gRPC`，不要写“高级消息队列协议”“面向切面编程”“Java 管理扩展”“Google 远程过程调用”或“中文全称 (英文缩写)”。
- REST API 导航项优先使用官方 endpoint ID；页面正文负责用中文解释 endpoint 用途。
- 普通句子中避免“conditions endpoint”“auto-configuration 类”“annotation 注解”这类混排，应分别写成“`conditions` 端点”“自动配置类”“注解”。
- 不擅自增删事实，不补充上游没有的信息。
